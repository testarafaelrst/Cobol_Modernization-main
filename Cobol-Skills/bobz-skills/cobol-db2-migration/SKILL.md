# Skill: DB2 Migration — COBOL II to Enterprise COBOL 6.5

Follow these steps when the user needs to migrate a DB2 COBOL II program.

## Step 1 — Read the Program and JCL

Identify:

1. Whether the JCL has a `DSNHPC` (DB2PREC) step
2. Any `DECLARE CURSOR` in the Procedure Division
3. `EXEC SQL INCLUDE` statements and where DCLGENs are searched
4. The `DBRMLIB` dataset name and DD location

## Step 2 — JCL: Replace DSNHPC with Integrated Coprocessor

```jcl
* REMOVE this entire step:
//DB2PREC  EXEC PGM=DSNHPC,
//             PARM='HOST(COBOL),VERSION(AUTO),APOSTSQL(YES)'
//DBRMLIB  DD DSN=BANCO.DBRMLIB(&MEMBER),DISP=SHR
//SYSCIN   DD DSN=&&DB2OUT,...
//SYSLIB   DD DSN=BANCO.DB2.DCLGEN,DISP=SHR
//SYSIN    DD DSN=BANCO.SRC(&MEMBER),DISP=SHR

* UPDATE the COBCOMP step:
*   1. Add SQL to PARM:
PARM='...,SQL,...'

*   2. Add DBRM DD to the compile step:
//DBRM DD DSN=BANCO.DBRMLIB(&MEMBER),DISP=SHR

*   3. Add DCLGEN library to SYSLIB concatenation:
//SYSLIB DD DSN=BANCO.DB2.DCLGEN,DISP=SHR

*   4. Point SYSIN directly to the original source:
//SYSIN DD DSN=BANCO.SRC(&MEMBER),DISP=SHR
```

Reference: `Cobol-Skills/skill-db2-migration.md` §"JCL: Replace DSNHPC".

## Step 3 — Move DECLARE CURSOR to Working-Storage

This is the most critical code change. With the integrated coprocessor,
`DECLARE CURSOR` **must** be in the DATA DIVISION.

Scan the entire Procedure Division for `EXEC SQL DECLARE ... CURSOR FOR`.
Move each one to Working-Storage Section, placed after `EXEC SQL INCLUDE SQLCA`.

```cobol
* BEFORE — COBOL II, cursor in Procedure Division (line ~530)
530    EXEC SQL
531        DECLARE MYCSRSOR CURSOR FOR
532        SELECT COL1 FROM TABLE WHERE KEY = :WS-KEY
533    END-EXEC

* AFTER — EC 6.5, cursor in Working-Storage Section
 WORKING-STORAGE SECTION.
     ...
     EXEC SQL INCLUDE SQLCA END-EXEC.
     EXEC SQL
         DECLARE MYCSRSOR CURSOR FOR
         SELECT COL1 FROM TABLE WHERE KEY = :WS-KEY
     END-EXEC.

* In Procedure Division — only OPEN, FETCH, CLOSE remain
     EXEC SQL OPEN  MYCSRSOR END-EXEC
     EXEC SQL FETCH MYCSRSOR INTO :WS-COL1 END-EXEC
     EXEC SQL CLOSE MYCSRSOR END-EXEC
```

## Step 4 — Verify EXEC SQL INCLUDE Placement

`EXEC SQL INCLUDE` for DCLGENs and SQLCA stays in the DATA DIVISION — no change
needed. Confirm each DCLGEN dataset is present in the SYSLIB concatenation
of the compile step (not the removed DSNHPC step).

## Step 5 — Re-run BIND

After recompilation, the DBRM in `BANCO.DBRMLIB` has been regenerated by the
coprocessor. The BIND must be re-executed:

```jcl
DSN SYSTEM(DB2P)
BIND PACKAGE(BANCPKG) -
     MEMBER(&MEMBER)  -
     LIBRARY('BANCO.DBRMLIB') -
     ISOLATION(CS) VALIDATE(BIND) ACTION(REPLACE)
END
```

## Step 6 — Produce Change Summary

Output a table: **Item** | **COBOL II** | **EC 6.5** | **Risk**.

Mark `DECLARE CURSOR` move as **High** — requires regression testing of all
SQL cursor loops. All other changes are **Low** (JCL structural only).
